## Карточка товара (поля)

| Поле OC | Смысл | Пример |
|---------|--------|--------|
| `product_description[…][name]` | Название | AIR JORDAN 11 BLACK |
| `model` | Модель (= имя) | AIR JORDAN 11 BLACK |
| `sku` / `upc` / `ean` | Артикул | `1577` |
| `price` | Цена BYN | `170.0000` |
| `quantity` | Суммарный qty (часто «грязная» цифра) | `100` |
| `manufacturer` | Бренд | NIKE |
| Опция **Размер** | Остаток **по размеру** | 41→1, 42→2, … |
| Изображения | Часто пусто / no_image | Клиент грузит сам |

**Важно:** живое наличие для витрины брать из **опций размера** (`product_option` / quantity по size), а не из общего `quantity` в шапке.

Пример (product_id=1916, артикул 1577):

| Размер | Кол-во |
|--------|--------|
| 40 | 0 (на сайте скрывать) |
| 41 | 1 |
| 42 | 2 |
| 43 | 2 |
| 44 | 2 |
| 45 | 1 |
| 46 | 0 |

Есть вкладка «Добавить размеры» (хелпер 36–41 / 40–46) — для нас не нужна, данные уже в «Опции».

## Как забираем в новую систему

1. **Готово (read-only):** выгрузка `Export / Import` → Products → XLSX  
   Листы: `Products`, `AdditionalImages`, `ProductOptions`, `ProductOptionValues`, …  
   Файл лежит локально у агента (`/tmp` / artifacts), **в git не коммитим**.
2. **Запасной:** обход карточек `catalog/product/edit` (name/sku/price/brand/sizes).
3. Фото: если в OC пусто — админ заливает в новой системе.
4. Заказы/клиентов/кассу **не** переносим (по ТЗ).

## Маппинг в нашу БД (черновик)

```
OC product     → products (name, brand, price, article/sku, barcode)
OC size option → product_sizes (size, qty)  // qty=0 не показывать на сайте
OC image       → product_images (если есть)
```

Артикул с OC (`sku`) можно сохранить; штрихкод для бирки — генерировать у нас (как в ТЗ), при желании связать с тем же числом.
