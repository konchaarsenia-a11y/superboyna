## Dual-scheme (важно)

| | LEGACY (старые) | RAW26 (новые с **2026-08-31**) |
|--|--|--|
| Формула | `сырьё×coef + 11 + 6×N + пакеты` | `Товар_raw = сырьё×M + recover`; `Цена = min(Товар_raw + 9×N + F + пакеты, 0.92×R)`. R — розница в тексте клиенту (товар + розничная доставка, если R/N < 80). Отдельного капа товара нет |
| M / coef по умолч. | 2.3 | **2.6** |
| Тег в wishes | нет / `[SCHEME:LEGACY]` | `[SCHEME:RAW26]` + `[COEF:2.6]` |
| Указанная цена на листе ПП | **не трогаем** автоматом | **не плывёт** при refresh/пересчёте; столбец «Факт стоимость» = указанная. Занос заказа ПП берёт **stated**, не calc fact |
| Календарь доставок | без изменений | без изменений (migrate тоже не трогает) |

Ручной перевод старого ПП: кнопка в карточке → action `migratePpToRaw26Scheme`.

**Оффер / сообщение клиенту (2026-09-20):** в тексте клиенту — **целое BYN** (`Math.round` от fact), либо ручная указанная (`statedTouched`). Внутри fact/cap/`clientPrice` остаются с копейками (rit_murr **157.50** → клиенту **158**). LEGACY — указанная как введена.

**Оффер / сообщение клиенту (2026-09-15):** RAW26 берёт **fact**, не завышенный stated. LEGACY — указанная.

**Крошка-миксер в RAW26 (канон 15/17/20):** кнопка «Крошки» — не фракция позиции. В сырьё ПП идёт `(г/100)×ставка`: овощи/фрукты **15**, мясные **17**, гипоаллергенные **20**. Дальше обычная RAW26 (`×M + recover + 9×N + пакеты + фракции`, кап). Нарезка разворачивает крошку в исходные позиции по `sources`/`ratio`. Фракция «Крошка» у SKU (не миксер) — в родителе, не в matcher наценок. Ставки миксера не меняли, когда крутили наценки фракций. Подробно: [FRACTION-MARKUP-CANON.md](./FRACTION-MARKUP-CANON.md).

**Указанная vs факт (2026-09-19):** refresh мини-аппа не переписывает `statedCost`. Внос заказа ПП подставляет цену с листа (указанная), не свежий calc.

**Потолок (2026-10-04, правило Арсения):** 92% от показанной розницы на всю цену, вместе с доставкой, фракцией и пакетами. Уже сохранённые карточки сами не переписываются.

```
Товар_raw = сырьё×M + recover
R         = Σрозница_строк + розничная доставка
            розничная доставка = 9×N, если (Σрозница)/N < 80, иначе 0
            это число из текста «в розницу выходит»
Цена      = min(Товар_raw + 9×N + F + пакеты, 0.92×R)
```

Компоненты (товар, `deliveryByn` = 9×N, F, пакеты) не сжимаются. Если черновик выше потолка, режется только итог. Если Σрозница = 0, потолок не применяется.

С 2026-10-03 до 2026-10-04 кап сидел только на товаре, и цена = товар + 9×N + F + пакеты могла быть выше розницы в тексте. dasha_2135 при новом потолке: N=1/2/4 → 58.88 / 67.16 / 83.72. rit_murr R 171.20 → цена 157.50. 1000 г лёгкого среднего, R 110 → 101.20.

**Чистые оффера RAW26** (не путать с месячным `getStats` при нарезчике OFF):  
`чистые = цена − сырьё − recover − пакеты − 4×N` (топливо как в `STATS_DELIVERY_FUEL_PER_`). Фракции и остаток доставки 5×N остаются в чистом. ## 0. Философия

1. **Зарабатывать только на сырье** — накрутка `M` только на `Σ(сырьё)`.
2. **Свет / нарезка / дойпак** — в цену **по себесу** (×1), без прибыли.
3. **Жевалки шт** — в сушилке почти не занимают место, режутся быстро → recover **мягкий** (`+0,50`), не `+2,40`.
4. **Полная цена ПП не выше 92% розницы в тексте клиенту** — R включает розничную доставку, если товар на доставку ниже 80. В потолок входят доставка 9×N, фракция и пакеты.
5. Пакеты/крафт УП4 — в формуле без наценки, но не выводят итог выше капа.

Раньше (ошибочно для твоей логики): накрутка на полный COGS → ты ещё «зарабатывал» 35% на свете и ЗП.

## 1. Формула новых ПП

```
recover_100г = 3,90          # свет+нарезка+дойпак — только возмещение
recover_шт   = 0,50          # жевалка: доля пака + чуть труда (не 2,40)

Товар_raw = Σ(сырьё)×M + Σ(recover)
фулфилмент = 9×N + пакеты + фракции
черновик = Товар_raw + фулфилмент
capBase = R_товара + (R_товара/N < 80 ? 9×N : 0)   # как «в розницу выходит»
цена = min(черновик, 0.92×capBase)                 # нет розницы → черновик
# компоненты не сжимаем: deliveryByn остаётся 9×N; пол товара цену над потолком не поднимает

вклад = Σ(сырьё)×(M−1) + (9−7)×N   # до капа; если кап сработал — вклад меньше
# recover и пакеты в нуле; с доставки +2 за шт доставки
```

| Параметр | Значение |
|----------|----------|
| **M на сырьё** | **2.60** база для новых (RAW26) |
| recover 100г | **3.90** |
| recover жевалка шт | **0.50** |
| F | **9** × N |
| Пакеты | pass-through |
| Старые ПП | без изменений `×2,3 + 11 + 6×N + пакеты` до ручного migrate |

### Жевалки

Старое `+2,40` на шт размазывало ЗП/свет как на 100г дрессуры — **криво** для корня/трахеи/уха.
Рабочая норма **0,50** (пак ~0,40 + чуть рук). Если по факту цеха мало — можно **0,30–0,40**.

## 4. Вердикт

- База новых: **M=2.60 только на сырьё**, recover 100г=3.9, жевалка=0.5.
- Полная цена RAW26 ≤ 92% от capBase (R≥80 → только Σ розницы; R<80 → Σ+9×N). Иначе ПП не имеет смысла против той розницы, которую клиент реально платит.
- Вклад ≈ `сырьё×(M−1) + 2×N` до капа; кап сжимает вклад, не розницу.
- Старые карточки и уже внесённые доставки не пересчитываются; перевод — вручную.
- Жевалки: не раздувать recover — иначе цена растёт без роста заработка на сырье.
